# 03 · 快速开始

> 目标：从零到"前端能对着接口开发"，全程不需要机械臂硬件。
> 环境：Windows 10/11 + Python 3.11+（本项目用 Anaconda 的 Python 3.13）+ uv

---

## 一、本机（Windows，无 Docker、无管理员权限）—— 便携版 PostgreSQL

本项目自带一套**便携版 PostgreSQL 17**：不注册 Windows 服务、不需要管理员权限，
数据目录在 `C:\pgruntime\pgdata`。

> **路径必须是纯 ASCII**。PostgreSQL 在中文路径下 `initdb` 会直接报
> `invalid byte sequence for encoding "UTF8"`，这是 Windows 编码问题，不是配置错误。
> 所以运行时刻意放在 `C:\pgruntime`，而不是项目目录里。可用环境变量 `PG_RUNTIME` 覆盖。

### 1.1 首次安装（只做一次）

1. 下载官方 binaries 包（约 315 MB，免安装）：
   `postgresql-17.6-1-windows-x64-binaries.zip`，来自
   `get.enterprisedb.com/postgresql/`
2. 解压到 `C:\pgruntime`，得到 `C:\pgruntime\pgsql\bin\...`
3. 初始化数据目录：

```powershell
& "C:\pgruntime\pgsql\bin\initdb.exe" -D "C:\pgruntime\pgdata" `
    -U pigadmin --auth=trust --encoding=UTF8 --locale=C
```

4. 在 `C:\pgruntime\pgdata\postgresql.conf` 末尾追加：

```ini
# ---- pig_injection_platform ----
port = 55432
listen_addresses = '127.0.0.1'
timezone = 'Asia/Shanghai'
```

### 1.2 日常启动 / 停止 / 查看

```powershell
cd <项目根目录>
powershell -ExecutionPolicy Bypass -File backend\scripts\pg_start.ps1
powershell -ExecutionPolicy Bypass -File backend\scripts\pg_status.ps1
powershell -ExecutionPolicy Bypass -File backend\scripts\pg_stop.ps1
```

> 脚本内部用 `Start-Process` 调 `pg_ctl`。**不要直接在 shell 里敲 `pg_ctl start`**：
> 子进程会继承标准输出句柄，导致命令永不返回（Windows 特有问题，不是数据库卡住）。

### 1.3 连接信息

| 项 | 值 |
|---|---|
| 主机 | `127.0.0.1` |
| 端口 | `55432` |
| 库 | `pig_injection` |
| 用户 | `pigadmin` |

### 1.4 建表 + 种子数据

```powershell
cd backend
uv run python scripts/init_db.py
uv run python scripts/init_db.py --drop   # 危险：删光重建（仅开发）
```

### 1.5 导出 DDL（给 DBA / 手工建库用）

```powershell
cd backend
uv run python scripts/dump_schema.py
```

## 二、服务器（有 Docker）—— 一键起

```bash
docker compose up -d
docker compose logs -f backend
```

会起两个容器：数据库（PostgreSQL 17，端口 55432）和后端（端口 8080），
并自动用 `backend/sql/schema.sql` 初始化表结构。

上线前请把 `docker-compose.yml` 里的示例密码改掉。

---

## 三、启动后端

```powershell
cd backend
uv sync
uv run uvicorn app.main:app --host 0.0.0.0 --port 8080 --reload
```

接口文档：http://127.0.0.1:8080/docs
健康检查：http://127.0.0.1:8080/api/v1/health

## 四、自检（端到端冒烟测试）

```powershell
cd backend
uv run python scripts/smoke_test.py
```

会按真实使用顺序打一遍全部接口（42 项断言）：

- 健康检查 / 概览 / 台账
- 机械臂状态、点动、幂等验证、回零、停止、模式切换
- 避障状态与开关、热成像直读与历史
- 完整自动注射流程（创建 → 定位 → 对位 → 进针 → 注药 → 退针 → 完成），
  并校验阶段耗时与过程事件时间线是否落库
- 报表接口、遥测历史、指令审计
- 急停链路：急停生效 → 状态变 estop → 运动指令被拒（HTTP 409）→ 复位成功

预期结尾输出：42/42 通过。

## 五、切换到真实机械臂

等外包方交付后，只改 `backend/.env`：

```ini
ARM_DRIVER=http
ARM_BASE_URL=http://192.168.1.50:6000
ARM_PATH_STATUS=/api/arm/status
ARM_PATH_JOG=/api/arm/jog
# ... 其余 ARM_PATH_* 按对方文档填
```

如果对方字段名和我们不一致（大概率不一致），只改
`backend/app/services/arm_gateway.py` 里 `HttpArmAdapter.get_status()` 的映射，
业务代码和前端一行都不用动。

改完重启后端，再跑一次冒烟测试，按错误码判断问题：

- `arm_unreachable`：网络或地址不对；
- `arm_rejected`：对方校验不通过，看响应 message；
- 字段为 null：补齐 `get_status()` 的映射。

## 七、常见问题

Q：`pg_ctl start` 卡住不返回？
A：正常，请用 `scripts/pg_start.ps1`（内部走 Start-Process）。数据库其实已经起来了。

Q：`initdb` 报 UTF8 编码错误？
A：路径里有中文，换到纯 ASCII 路径（如 `C:\pgruntime`）。

Q：端口 55432 被占用？
A：改 `postgresql.conf` 的 port，同步改 `backend/.env` 的 `DATABASE_URL`
和 `scripts/pg_*.ps1` 的 `-Port` 参数。

Q：health 里 arm_online 为 false？
A：`ARM_DRIVER=http` 时说明连不上机械臂（真机未上线时正常）；mock 模式下不应出现。

Q：想重置演示数据？
A：`uv run python scripts/init_db.py --drop`。
