## 0. 三条必须遵守的约定

### 0.1 所有写操作都要带 `request_id`（幂等键）

后端保证：**相同 `request_id` 重复提交只会向机械臂下发一次**，第二次直接返回第一次的结果
（响应里 `message` 会提示"重复请求"）。

前端请在用户点击时生成一个 UUID 并随请求发出。这样即使：
- 用户双击按钮；
- 网络超时后前端自动重试；
- 页面刷新导致请求重发；

也不会出现"机械臂打两针"。

```js
async function send(path, body) {
  const requestId = crypto.randomUUID();
  return fetch(base + path, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ ...body, request_id: requestId }),
  }).then(r => r.json());
}
```

### 0.2 控制类接口一律不要用 `GET`，也不要用 `fetch` 的自动重试

急停、点动、注射这类接口只走 `POST`，且**不要**在 `fetch` 层做自动重试——
重试请由用户操作触发（并且有了 `request_id`，重试是安全的）。

### 0.3 错误响应统一长这样

```json
{
  "ok": false,
  "error": "estop_active",
  "message": "急停状态下不接受运动指令",
  "request_id": "df1ebf4e-2a08-443c-b230-e72a4870a296"
}
```

| HTTP | `error` 常见值 | 含义 | 前端应该做什么 |
|---|---|---|---|
| 400 | `bad_request` / `bad_axis` / `bad_mode` | 参数错误 | 提示用户，不改状态 |
| 404 | `device_not_found` / `not_found` | 对象不存在 | 刷新列表 |
| 409 | `estop_active` | 急停未复位 | **弹红色警告**，引导去急停复位 |
| 409 | `arm_fault` | 机械臂故障 | 弹红色警告，显示 `message` |
| 409 | `injection_busy` | 已有注射在执行 | 提示等待或中止 |
| 409 | `arm_rejected` | 机械臂拒绝执行 | 显示 `message` |
| 501 | `unsupported` | 该机械臂不支持此功能 | 置灰按钮 |
| 502/503 | `arm_unreachable` | 连不上机械臂 | 显示"设备离线"角标 |
| 504 | `arm_timeout` | 机械臂响应超时 | 提示重试；先查状态再决定是否重发 |

成功响应统一包含 `ok: true`。

## 1. 实时推送（推荐，替代高频轮询）

### `WS /api/v1/ws`

连接后服务端**立刻推一次**当前状态，之后持续推送。客户端只需定时发 `"ping"` 保活。

```js
const ws = new WebSocket(`ws://${host}/api/v1/ws`);
ws.onmessage = (e) => {
  const msg = JSON.parse(e.data);
  switch (msg.type) {
    case 'arm_status':      renderArmStatus(msg.data); break;   // 机械臂实时状态，约 1 次/秒
    case 'control_command': toastCommand(msg.data); break;      // 指令下发结果
    case 'injection_phase': updatePhase(msg.data); break;       // 注射阶段变化
    case 'injection_task':  onTaskFinished(msg.data); break;    // 任务终态
    case 'obstacle':        warnObstacle(msg.data); break;      // 避障事件
  }
};
setInterval(() => ws.readyState === 1 && ws.send('ping'), 20000);
```

`arm_status` 的 `data` 字段与 `GET /api/v1/arm/status` 完全一致。

### 2.3 手动控制

所有控制接口的**公共请求字段**：

| 字段 | 类型 | 说明 |
|---|---|---|
| `request_id` | string | 幂等键，建议 UUID |
| `operator_id` | int | 操作员 ID（可选，用于审计） |
| `operator_name` | string | 操作员姓名（可选） |
| `device_code` | string | 默认 `ARM-01` |

所有控制接口的**成功响应**统一为：

```json
{
  "request_id": "92a891fe-...",
  "command_type": "jog",
  "accepted": true,
  "result": "success",
  "arm_command_id": "JOG-1758100000123",
  "message": null,
  "duration_ms": 3,
  "response": { "accepted": true, "motion_done": true }
}
```

| 方法 | 路径 | 请求体（除公共字段外） |
|---|---|---|
| POST | `/api/v1/arm/jog` | `axis`(`x`/`y`/`z`/`j1`..`j6`)、`direction`(1/-1)、`step`(>0)、`speed_pct`(1-100) |
| POST | `/api/v1/arm/move/pose` | `pose{x,y,z,rx,ry,rz}`、`speed_pct`、`frame` |
| POST | `/api/v1/arm/move/joint` | `joint_angles_deg[]`、`speed_pct` |
| POST | `/api/v1/arm/home` | 无（只传公共字段） |
| POST | `/api/v1/arm/stop` | 无 |
| POST | `/api/v1/arm/estop` | 无。**必须做成独立大按钮，任何状态下可点，且允许连点** |
| POST | `/api/v1/arm/estop/reset` | 无。成功后一般还要调 `/arm/home` |
| POST | `/api/v1/arm/mode` | `mode`(`idle`/`manual`/`auto`) |

**交互建议**：点动按钮用 `pointerdown` 开始、`pointerup` 停止；由于后端做了幂等，
连点安全。急停按钮不要做二次确认弹窗——急停要快。

### 2.6 自动注射（核心业务）

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/v1/injection/tasks` | 创建任务；`auto_start=true` 时立即执行 |
| POST | `/api/v1/injection/tasks/{id}/start` | 启动已创建的任务 |
| POST | `/api/v1/injection/tasks/{id}/abort` | 中止：`{reason: "operator_abort"}` |
| GET | `/api/v1/injection/tasks` | 列表（分页 + `status`/`pen_id`/`pig_id` 过滤） |
| GET | `/api/v1/injection/tasks/active` | 正在执行的 |
| GET | `/api/v1/injection/tasks/{id}` | 详情 + `events[]` + `media[]` |
| GET | `/api/v1/injection/tasks/{id}/events` | 只取时间线 |

创建请求：

```json
{
  "request_id": "uuid",
  "pen_id": 1,
  "pig_id": 1,
  "mode": "auto",
  "drug_name": "猪瘟疫苗",
  "drug_batch_no": "B20260917",
  "dose_target_ml": 2.0,
  "depth_mm": 3.5,
  "needle_id": "N-001",
  "target_source": "guardrail_camera",
  "target_point_base": { "x": 420.0, "y": 30.0, "z": 760.0 },
  "target_confidence": 0.93,
  "auto_start": true
}
```

**任务状态机**（前端按这个渲染进度条）：

```
created → queued → locating → aligning → inserting → injecting → retracting → completed
                                                                          ↘ failed
                                        （任意阶段可 abort）                ↘ aborted
```

对应中文标签：定位注射点 / 机械臂对位 / 进针 / 注药 / 退针 / 完成。

**前端推荐用法**：创建后拿到 `data.id`，然后：
1. 靠 WebSocket 的 `injection_phase` 实时更新进度；
2. 收到 `injection_task` 且 `status=completed/failed` 时，调 `GET /injection/tasks/{id}` 拉完整详情做结果页。

若不用 WebSocket，就每 500ms 轮询 `GET /injection/tasks/{id}` 直到 `status` 落在终态。

## 4. 当前不提供的能力（别等我们）

- **鉴权**：v1 没有 Token / 登录态，只允许部署在可信局域网。后续加 JWT 时会保持接口路径不变。
- **视频流**：热成像/可见光的实时视频流不在本服务内，需要时另开接口。
- **实时轨迹回放**：目前只存遥测采样点，未做轨迹动画接口。
- **任务队列调度**：一次只能有一个注射任务在执行，同时提交第二个会被机械臂拒绝（`injection_busy`）。
- **修改历史数据**：`injection_tasks` / `control_commands` / `alarms` 是审计数据，只能追加不能改。

## 5. 联调起步（无硬件也能跑）

后端默认 `ARM_DRIVER=mock`，内置一台会动、会报错、会触发避障的仿真机械臂。
真机未到位前，前端可以直接对着它开发：

```bash
# 1. 起数据库（详见 docs/03_快速开始.md）
powershell -File backend/scripts/pg_start.ps1

# 2. 起后端
cd backend && uv run uvicorn app.main:app --host 0.0.0.0 --port 8080 --reload

# 3. 自检
uv run python scripts/smoke_test.py
```

拿到外包方的真机接口后，只改 `backend/.env` 里的 `ARM_DRIVER=http` 与 `ARM_PATH_*`，
前端代码一行都不用动。
